# Project instructions

- DO NOT USE SUBAGENTS. Work in the main agent only; do not spawn, delegate to, or message other agents. This is an explicit user requirement.
- Do not use n8n in the application, demo, orchestration, or deployment.
- Speed and verified application completion are the product priorities. Measure discovery, preparation, submission, and confirmation separately.
- Never present a queued task, a filled form, an HTTP 200 without a valid receipt, or an SMTP acceptance as a confirmed employer application.
- Keep local benchmarks, public read-only probes, and real application results visibly distinct. Preserve raw benchmark output and reproducible commands.
- Use D: for project files, environments, downloads, and benchmark artifacts on this machine.
- Design for ordinary CPU-only laptops; a GPU is optional. Do not run GPU inference or download models while the user's GPU is in use. Prioritize conceptual architecture and job discovery, then application execution; model experiments come later.
- Do not make LLMs a dependency for discovery, matching, or known-form execution. Compare rules, small classifiers, retrieval, and templates before adding generative models.
- Do not commit credentials, browser profiles, candidate documents, personal profiles, or application contents.
- Tests submit only synthetic data to this project's loopback or hosted sandbox receivers. Real email or employer submissions need explicit user authorization for the reviewed batch.
